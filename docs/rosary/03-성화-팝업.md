# 03. 성화 팝업

신비 선포 화면(인덱스 6·20·34·48·62)의 성화를 누르면 전체화면으로 크게 보며 묵상을 읽는 팝업입니다.

다루는 파일: `src/components/MysteryImageDialog.tsx`

> ⚠️ **먼저 알아 둘 것**: 코드에는 닫는 방법이 세 가지(닫기 버튼·ESC·배경 클릭) 있어 보이지만, **실제로 의도대로 동작하는 것은 닫기 버튼 하나뿐입니다.** 브라우저로 실측한 결과입니다.
>
> | 방법 | 기대 | 실제 |
> |---|---|---|
> | 닫기 버튼 | 성화 팝업만 닫힘 | ✅ 그대로 |
> | **ESC** | 성화 팝업만 닫힘 | ❌ **기도문 창까지 함께 닫힘** |
> | **배경 클릭** | 성화 팝업 닫힘 | ❌ **아무 일도 없음** |
>
> 이유는 §3 에서 설명합니다. 이 문서를 쓰기 위한 조사에서 발견했고, **아직 고치지 않았습니다**([06-알려진-문제](06-알려진-문제.md) §16·§17).

---

## 1. 왜 `<dialog>` 인가

직접 만든 `<div>` 오버레이 대신 브라우저 기본 `<dialog>` + `showModal()` 을 씁니다. 그러면 브라우저가 알아서 해 주는 것들이 있습니다.

| 브라우저가 해 주는 일 | 직접 만들면 |
|---|---|
| 화면 맨 위 레이어(top layer)에 올림 | z-index 를 다른 요소와 다퉈야 함 |
| 팝업 밖 요소를 못 누르게 막음 | 뒤에 투명 막을 깔아야 함 |
| 키보드 초점이 팝업 안에 갇힘(포커스 트랩) | 직접 구현해야 함 — 꽤 어려움 |
| ESC 키를 받아 줌 | 리스너를 붙였다 떼야 함 |
| 배경 어둡게(`::backdrop`) | 별도 요소가 필요 |

이 저장소의 모든 모달이 이 방식입니다 — `ConfirmDialog`, `PrayerTextDialog`, `SplashOverlay`, 그리고 이 팝업.

---

## 2. 여는 방식이 다른 다이얼로그와 다르다

### 다른 다이얼로그 — `useEffect`

`ConfirmDialog` 나 `PrayerTextDialog` 는 **항상 렌더돼 있고** `open` 값만 오갑니다.

```tsx
// PrayerTextDialog.tsx 의 방식
useEffect(() => {
  const dialog = ref.current;
  if (!dialog) return;
  if (open && !dialog.open) dialog.showModal();
  if (!open && dialog.open) dialog.close();
}, [open]);
```

열고 닫는 두 방향을 다 처리해야 하므로 effect 가 필요합니다.

### 성화 팝업 — 콜백 ref

여기는 부모가 **있을 때만** 이 컴포넌트를 렌더합니다.

```tsx
{fullScreenImage && (
  <MysteryImageDialog … onClose={() => setFullScreenImage(null)} />
)}
```

즉 **마운트되는 순간이 곧 열리는 순간**이고, 사라지는 순간이 곧 닫히는 순간입니다. 그래서 "요소가 붙는 그 순간" 한 번만 실행되는 콜백 ref 로 충분합니다.

```tsx
<dialog
  ref={(el) => {
    if (el && !el.open) {
      el.showModal();
    }
  }}
>
```

**닫는 코드가 없습니다.** 컴포넌트가 사라지면서 `<dialog>` 요소 자체가 DOM 에서 제거되기 때문입니다.

### 콜백 ref 란

`ref` 자리에 객체 대신 **함수**를 넣는 방식입니다. React 가 두 번 불러 줍니다.

```
요소가 붙을 때  →  ref(그 DOM 요소)
요소가 떨어질 때 →  ref(null)
```

그래서 `if (el && ...)` 로 검사해야 합니다. `null` 일 때 `el.showModal()` 을 부르면 터집니다.

## 3. 닫는 방법 — 코드와 실제

### (1) ESC 키 — `onCancel` ❌ 기도문 창까지 닫힌다

```tsx
onCancel={(e) => {
  e.preventDefault();
  onClose();
}}
```

`preventDefault()` 가 핵심입니다. 브라우저 기본 동작(그냥 닫기)을 막고 **React state 로만 닫습니다.**

막지 않으면 어떻게 될까요? 화면에서는 팝업이 사라지는데 부모의 `fullScreenImage` 는 아직 값이 남아 있습니다. 그러면 React 는 "팝업이 열려 있다"고 믿고 있으므로, 같은 성화를 다시 눌러도 아무 일이 일어나지 않습니다.

**이 저장소의 모든 `<dialog>` 가 같은 패턴을 씁니다.** 화면과 상태가 어긋나지 않게 하려는 것입니다.

#### 그런데 실제로는 두 창이 함께 닫힙니다

브라우저로 재보면 ESC 한 번에 성화 팝업**과** 기도문 창이 **둘 다** 닫힙니다.

원인은 React 의 이벤트 처리 방식입니다. 네이티브 `cancel` 이벤트는 원래 **버블링하지 않습니다**(부모로 올라가지 않음). 그런데 React 는 이런 이벤트를 최상위 컨테이너에서 한꺼번에 받아 **자기 컴포넌트 트리를 따라** 다시 전달합니다. 그래서 `MysteryImageDialog` 의 `onCancel` 뿐 아니라, 컴포넌트 트리에서 그 위에 있는 `PrayerTextDialog` 의 `onCancel` 까지 불립니다.

`e.preventDefault()` 는 **브라우저의 기본 닫기**를 막을 뿐, React 가 부모 핸들러를 부르는 것은 막지 못합니다. 막으려면 전파를 멈춰야 합니다.

```tsx
onCancel={(e) => {
  e.preventDefault();
  e.stopPropagation();   // ← 이게 있어야 부모 다이얼로그가 안 닫힌다
  onClose();
}}
```

*이 문서에서는 고치지 않았습니다 — [연습문제](05-연습문제.md)의 재료로 남겨 두었습니다.*

### (2) 배경 클릭 — `onClick` ❌ 실제로는 닫히지 않는다

```tsx
onClick={(e) => {
  if (e.target === e.currentTarget) {
    onClose();
  }
}}
```

`e.target` 은 **실제로 눌린 요소**, `e.currentTarget` 은 **이 핸들러가 붙은 요소**(`<dialog>`)입니다. 둘이 같다는 건 "팝업 안쪽 내용이 아니라 `<dialog>` 자기 자신(= 어두운 배경)이 눌렸다"는 뜻입니다.

이 검사가 없으면 팝업 안의 글자를 눌러도 닫힙니다. 클릭 이벤트는 자식에서 부모로 거슬러 올라가기 때문입니다(버블링).

#### 그런데 실제로는 절대 닫히지 않습니다

이 팝업의 CSS 를 보면 이유가 보입니다.

```css
.fullScreenDialog { width: 100vw; height: 100vh; }   /* 화면 전체 */
.fullScreenContent { width: 100%; height: 100%; }    /* 그 안을 또 꽉 채움 */
```

`<dialog>` 가 화면을 꽉 채우고, 그 안의 `.fullScreenContent` 가 `<dialog>` 를 다시 꽉 채웁니다. **결과적으로 화면 어디를 눌러도 눌리는 것은 `.fullScreenContent` 이지 `<dialog>` 자신이 아닙니다.** 그래서 `e.target === e.currentTarget` 이 절대 참이 되지 않습니다.

원래 이 관용구는 "다이얼로그가 화면 가운데 떠 있고 그 바깥의 어두운 부분"을 누르는 상황을 위한 것인데, 여기는 그 바깥이 존재하지 않습니다.

*이것도 고치지 않고 남겨 두었습니다.*

### (3) 닫기 버튼

```tsx
<button type="button" className={styles.closeFullScreenBtn} onClick={onClose}
        aria-label={t("common.close")}>
  <svg viewBox="0 0 24 24" … aria-hidden="true"> … </svg>
</button>
```

- `aria-label` — 버튼 안이 그림뿐이라 스크린 리더가 읽을 글자가 없습니다. 이름을 따로 붙여 줍니다
- `aria-hidden="true"` — 그림은 장식이므로 읽지 않게 합니다

## 4. 내용

```tsx
<div className={styles.fullScreenScroll}>
  <h2 className={styles.fullScreenTitle}>{title}</h2>
  <img src={src} alt={title} className={styles.fullScreenImg} />
  <div className={styles.fullScreenText}>
    {explanation.map((line, i) => (
      <p key={i} className={styles.fullScreenLine}>
        {i + 1}. {line}
      </p>
    ))}
  </div>
</div>
```

**번호(`1.` `2.` …)는 데이터에 없습니다.** 여기서 붙입니다. 그래서 묵상 문장을 추가하거나 순서를 바꿔도 번호는 알아서 따라옵니다.

## 5. 언제 열리나 — 부모의 결정

팝업을 열지 말지는 `RosaryGuide` 가 정합니다.

```tsx
const canOpenImage = Boolean(step.image && step.explanation && step.explanation.length > 0);
const openImage = canOpenImage
  ? () => setFullScreenImage({ src: step.image!, title: step.title, explanation: step.explanation! })
  : undefined;
```

그리고 `RosaryStepView` 로 넘깁니다.

```tsx
<img onClick={onImageClick} style={{ cursor: canOpenImage ? "pointer" : "default" }} />
```

**묵상이 없으면 핸들러 자체를 넘기지 않습니다.** 그래서 눌러도 아무 일이 없고, 커서 모양도 손가락이 아닙니다.

여기서 영어 모드의 동작이 설명됩니다. 영어에는 묵상 데이터가 없어 `explanation` 이 항상 `[]` 이고, 따라서 **영어로 보면 성화를 눌러도 반응이 없습니다.** ([01-데이터 §6](01-데이터.md#6-묵상-문장))

> `step.image!` 의 `!` 는 "여기 값이 절대 없지 않다"고 컴파일러에게 우기는 표시입니다. 바로 위 `canOpenImage` 에서 확인했으므로 안전하지만, **실제 검사는 하지 않으므로** 남용하면 위험합니다. → [치트시트 §5](../typescript-for-python.md#5-널-다루기)

## 6. CSS

```css
.fullScreenDialog {
  position: fixed; inset: 0;
  width: 100vw; height: 100vh;
  margin: 0; padding: 0; border: none;
  background: transparent;
  max-width: none; max-height: none;   /* <dialog> 기본 크기 제한 해제 */
}

.fullScreenDialog::backdrop {
  background: rgba(0, 0, 0, 0.85);
  backdrop-filter: blur(4px);
}
```

`max-width: none` 이 필요한 이유: 브라우저는 `<dialog>` 에 기본 최대 크기를 걸어 둡니다. 전체화면으로 쓰려면 풀어 줘야 합니다.

`::backdrop` 은 `<dialog>` 전용 가상 요소입니다. `showModal()` 로 열었을 때만 생기며, 배경을 어둡게 하는 별도 요소를 만들 필요가 없습니다.

```css
.fullScreenLine {
  word-break: keep-all;   /* 한국어 단어가 중간에서 잘리지 않게 */
}
```

## 7. 지금 남아 있는 문제

| 문제 | 설명 |
|---|---|
| **ESC 가 두 창을 함께 닫는다** | §3-(1). `e.stopPropagation()` 이 빠졌습니다 |
| **배경 클릭이 동작하지 않는다** | §3-(2). 팝업이 화면을 꽉 채워 "배경"이 존재하지 않습니다 |
| **키보드로 열 수 없다** | 트리거가 `<img onClick>` 이라 Tab 으로 초점이 가지 않고 Enter 로 누를 수도 없습니다. `<button>` 으로 감싸야 합니다 → [연습문제 고급 12번](05-연습문제.md) |
| **모달이 2중이다** | 이 팝업은 `PrayerTextDialog` 의 `<dialog>` **안에서** `showModal()` 을 부릅니다. `RosaryGuide` 의 기록 확인창은 "모달을 두 겹 쌓지 않으려고" 인라인으로 만들었는데, 여기는 그 원칙이 지켜지지 않았습니다. 위의 ESC 문제도 결국 여기서 나옵니다 |
| **`100vh`** | 모바일 브라우저에서 주소창이 나타났다 사라지면 높이가 달라져 잘릴 수 있습니다. `100dvh` 가 요즘 방식입니다 |

자세한 내용은 [06-알려진-문제](06-알려진-문제.md).
