# 01. 데이터 — 77장은 어떻게 만들어지는가

이 장이 묵주기도 기능의 **심장**입니다. 여기만 이해하면 나머지는 그 위에 얹힌 껍데기입니다.

다루는 파일: `src/lib/rosaryMysteries.ts` · `src/lib/rosaryMeditations.ts` · `src/lib/prayerTexts.ts`

---

## 1. 왜 "평평한 배열"인가

묵주기도는 구조가 있는 기도입니다. 5단이 있고, 각 단 안에 성모송 10번이 있고… 자연스럽게 떠오르는 자료 구조는 중첩입니다.

```python
# 자연스럽지만 이 앱에는 안 맞는 모양
rosary = {
    "opening": [...],
    "decades": [
        {"mystery": "...", "hail_marys": [...]},
        ...
    ],
    "closing": [...],
}
```

이 앱은 그렇게 하지 않습니다. **화면 한 장 = 배열 한 칸**인 **평평한 배열** 하나로 만듭니다.

```
[0] 사도신경  [1] 주님의 기도  [2] 성모송 1/3  ...  [76] 성모찬송
```

이유는 단순합니다. 화면이 하는 일이 "한 장씩 넘기기"이기 때문입니다. 평평하게 두면 **인덱스 숫자 하나**만 있으면 됩니다.

```ts
const handleNext = () => setIndex(index + 1);   // 이게 전부
```

중첩 구조였다면 넘길 때마다 "지금 3단의 7번째 성모송이니까 다음은…" 을 계산해야 합니다. 자료 구조를 화면이 쓰기 좋은 모양으로 바꾼 것입니다.

## 2. 77이라는 숫자

`src/lib/rosaryMysteries.ts` 의 `buildRosarySteps` 가 만듭니다.

| 구간 | 내용 | 장수 |
|---|---|---:|
| 시작 | 사도신경 1 + 주님의 기도 1 + 성모송 3 + 영광송 1 | **6** |
| 각 단 | 신비 선포 1 + 주님의 기도 1 + 성모송 10 + 영광송 1 + 구원기도 1 = 14<br>× 5단 | **70** |
| 마침 | 성모찬송 1 | **1** |
| | | **77** |

```
6 + (1 + 1 + 10 + 1 + 1) × 5 + 1 = 6 + 70 + 1 = 77
```

관련 상수는 전부 이름이 붙어 있습니다.

```ts
export const DECADES_PER_ROSARY = 5;     // 한 묵주기도 = 5단
export const HAIL_MARYS_PER_DECADE = 10; // 한 단 = 성모송 10번
const OPENING_HAIL_MARYS = 3;            // 시작 성모송 3번
```

### 인덱스 지도 (실제 데이터로 확인한 값)

```
 0  사도신경
 1  주님의 기도
 2  성모송 1/3
 3  성모송 2/3
 4  성모송 3/3
 5  영광송
────────────────────── 1단 시작
 6  ★ 1단 신비 선포   ← 성화 있음
 7  주님의 기도
 8  성모송 1/10
 …
17  성모송 10/10
18  영광송
19  구원을 비는 기도
────────────────────── 2단 시작
20  ★ 2단 신비 선포   ← 성화 있음
 …
34  ★ 3단 신비 선포
48  ★ 4단 신비 선포
62  ★ 5단 신비 선포
 …
75  구원을 비는 기도
76  성모찬송
```

**공식**: n단 블록의 시작 인덱스 = `6 + (n - 1) × 14`

> 확인해 보기: 3단의 성모송 7번째는 몇 번일까요?
> `6 + 2×14 = 34`(신비 선포) → `+1` 주님의 기도 → `+7` 일곱 번째 성모송 = **42**

## 3. 코드를 한 줄씩

```ts
return [
  { title: labels.creed, lines: creed },
  { title: labels.ourFather, lines: ourFather },
  ...hailMarys(OPENING_HAIL_MARYS),
  { title: labels.gloryBe, lines: gloryBe },
  ...Array.from({ length: DECADES_PER_ROSARY }, (_, d) => {
    const meditation = numberMeditation(mystery.lines[d], d + 1);  // "1단: …" → "1. …"
    return [
      { title: meditation, lines: [], decade: d + 1, image: ..., explanation: ... },
      { title: labels.ourFather, lines: ourFather, decade: d + 1, meditation },
      ...hailMarys(HAIL_MARYS_PER_DECADE, d + 1, meditation),
      { title: labels.gloryBe, lines: gloryBe, decade: d + 1, meditation },
      { title: labels.salvation, lines: salvation, decade: d + 1, meditation },
    ];
  }).flat(),
  { title: labels.closing, lines: closing },
];
```

화면에 쓰는 문장은 `numberMeditation` 이 "N단: " 접두어를 "N. " 번호로 바꿉니다 — "1단: 예수님께서 …" → "1. 예수님께서 …". 몇 번째 단인지는 이 번호가 알려 주고, 창 제목 라인은 오늘의 신비만("묵주기도 · 영광의 신비(수·일)", `getMysteryShortHeading` 으로 요일 축약) 보여 줍니다. 원본 데이터(`ROSARY_MYSTERY_SECTIONS`)는 그대로 둡니다 — lab 페이지 등 다른 곳은 원문을 씁니다.

파이썬으로 옮기면 이렇습니다.

```python
return [
    {"title": labels.creed, "lines": creed},
    {"title": labels.our_father, "lines": our_father},
    *hail_marys(OPENING_HAIL_MARYS),          # ← ...hailMarys(...) 와 같음
    {"title": labels.glory_be, "lines": glory_be},
    *[step
      for d in range(DECADES_PER_ROSARY)      # ← Array.from({length: 5}, ...)
      for meditation in [number_meditation(mystery.lines[d], d + 1)]
      for step in [                           # ← .flat()
          {"title": meditation, "lines": [], "decade": d + 1, ...},
          {"title": labels.our_father, "lines": our_father, "decade": d + 1, "meditation": meditation},
          *hail_marys(HAIL_MARYS_PER_DECADE, d + 1, meditation),
          {"title": labels.glory_be, "lines": glory_be, "decade": d + 1, "meditation": meditation},
          {"title": labels.salvation, "lines": salvation, "decade": d + 1, "meditation": meditation},
      ]],
    {"title": labels.closing, "lines": closing},
]
```

### `Array.from` + `.flat()` 이 하는 일

```
Array.from({ length: 5 }, (_, d) => [ 14장 ])
   → [ [14장], [14장], [14장], [14장], [14장] ]     ← 배열 5개가 든 배열

.flat()
   → [ 70장 ]                                      ← 한 겹만 펴서 평평하게
```

`.flat()` 은 **한 겹만** 폅니다. 그래서 안쪽의 `hailMarys(10, d+1)` 은 `...` 로 미리 풀어 둬야 합니다. 안 그러면 배열이 통째로 한 칸에 들어가 `.flat()` 한 번으로는 다 펴지지 않습니다.

### `hailMarys` 헬퍼

```ts
const hailMarys = (count: number, decade?: number, meditation?: string): RosaryStep[] =>
  Array.from({ length: count }, (_, i) => ({
    title: labels.hailMary,
    ordinal: `${i + 1} / ${count}`,   // "7 / 10"
    lines: hailMary,
    decade,
    meditation,
  }));
```

`Array.from({length: n}, (_, i) => ...)` 는 파이썬의 `[f(i) for i in range(n)]` 입니다.

> ⚠️ 화살표 함수가 `({` 로 시작하는 데 주의하세요. 소괄호가 없으면 `{` 를 코드 블록으로 읽어서 아무것도 안 돌려줍니다. → [치트시트 §2](../typescript-for-python.md#2-함수와-화살표)

## 4. RosaryStep — 화면 한 장의 모양

```ts
export interface RosaryStep {
  title: string;          // 큰 글씨
  ordinal?: string;       // "3 / 10" — 반복되는 기도에만
  lines: string[];        // 기도문 본문. 한 줄 = 한 문단
  decade?: number;        // 1~5. 시작·마침 기도에는 없음
  meditation?: string;    // 단 내내 위에 떠 있는 "N. 묵상 문장". 선포·시작·마침에는 없음
  image?: string;         // 성화 경로. 신비 선포 화면에만
  explanation?: string[]; // 묵상 문장. 한국어일 때만
}
```

| 화면 종류 | title | ordinal | lines | decade | meditation | image | explanation |
|---|---|---|---|---|---|---|---|
| 사도신경 | 기도 이름 | — | 10줄 | — | — | — | — |
| 시작 성모송 | 기도 이름 | `1 / 3` | 5줄 | — | — | — | — |
| **신비 선포** | **신비 문장 자체** | — | **빈 배열** | 1~5 | — | ✅ | 한국어면 10~11문장 |
| 단 성모송 | 기도 이름 | `7 / 10` | 5줄 | 1~5 | ✅ | — | — |
| 성모찬송 | 기도 이름 | — | 11줄 | — | — | — | — |

**신비 선포 화면만 `lines` 가 빈 배열입니다.** 제목이 곧 본문 전체이기 때문입니다("1. 마리아께서 예수님을 잉태하심을 묵상합시다" — "N단:" 대신 "N." 번호를 씁니다). 같은 이유로 선포 화면에는 `meditation` 도 없습니다 — 제목과 같은 문장이 두 번 보이기 때문입니다. 화면 코드에 이런 가드가 있습니다.

```tsx
{step.lines.length > 0 && ( <div className={styles.body}>…</div> )}
```

## 5. 요일 → 신비

```ts
const MYSTERY_BY_WEEKDAY: MysteryId[] = [
  "glorious",   // 0 일요일 — 영광
  "joyful",     // 1 월요일 — 환희
  "sorrowful",  // 2 화요일 — 고통
  "glorious",   // 3 수요일 — 영광
  "luminous",   // 4 목요일 — 빛
  "sorrowful",  // 5 금요일 — 고통
  "joyful",     // 6 토요일 — 환희
];

export function getMysteryIdForDate(date: Date): MysteryId {
  return MYSTERY_BY_WEEKDAY[date.getDay()];
}
```

`Date.getDay()` 가 0(일)~6(토)을 주므로 배열 인덱스로 그대로 씁니다.

### 왜 브라우저에서만 불러야 하나

이 앱은 빌드할 때 화면을 미리 HTML 로 만들어 둡니다(`output: "export"`). 그 시점의 "오늘"은 **배포한 날**이지 사용자가 앱을 여는 날이 아닙니다. 그래서 `RosaryGuide` 는 이렇게 씁니다.

```tsx
const [mysteryId, setMysteryId] = useState<MysteryId | null>(null);   // 처음엔 null

useEffect(() => {
  setMysteryId(getMysteryIdForDate(new Date()));   // 브라우저에서만 실행됨
}, []);
```

`null` 인 동안에는 아무것도 그리지 않습니다(`if (!mysteryId ...) return null`).

### ⚠️ 숨은 결합 하나

신비 명칭은 `prayerTexts.ts` 의 배열에 있고, 그 배열의 **순서**로 찾습니다.

```ts
export const MYSTERY_ORDER: MysteryId[] = ["joyful", "sorrowful", "glorious", "luminous"];

export function getMysterySection(id, language) {
  const sections = language === "ko" ? ROSARY_MYSTERY_SECTIONS_KO : ROSARY_MYSTERY_SECTIONS_EN;
  return sections[MYSTERY_ORDER.indexOf(id)];   // ← 순서로 찾는다
}
```

**`MYSTERY_ORDER` 와 `prayerTexts.ts` 의 섹션 순서가 어긋나면, 에러 없이 조용히 엉뚱한 신비가 나옵니다.** 둘 중 하나를 건드릴 일이 생기면 반드시 양쪽을 함께 확인하세요.

## 6. 묵상 문장

`src/lib/rosaryMeditations.ts` 에 있습니다.

```ts
export const MYSTERY_MEDITATIONS: Record<MysteryId, Record<number, string[]>> = {
  joyful: {
    "1": ["삼위일체의 하느님은 …", "동정녀 마리아가 …", ...],   // 11문장
    "2": [...],
    ...
  },
  ...
};
```

파이썬으로는 `dict[MysteryId, dict[int, list[str]]]` 입니다.

- 대개 앞 **10문장이 성모송 10번에 하나씩** 대응하고, 마지막 한 문장은 꽃다발을 바치는 마무리 봉헌문입니다
- 화면에는 `1.` `2.` … 번호가 **자동으로** 붙습니다. 데이터에는 번호가 없습니다

### 붙는 자리

묵상은 성모송 화면이 아니라 **각 단의 신비 선포 화면 하나에 통째로** 붙습니다.

```ts
explanation: ko && MYSTERY_MEDITATIONS[id]?.[d + 1] ? MYSTERY_MEDITATIONS[id][d + 1] : []
```

이 한 줄을 뜯어보면:

| 조각 | 뜻 |
|---|---|
| `ko &&` | 한국어일 때만. 아니면 곧바로 `[]` |
| `MYSTERY_MEDITATIONS[id]?.[d + 1]` | 그 신비의 그 단 묵상. 없으면 `undefined` ([`?.` 설명](../typescript-for-python.md#5-널-다루기)) |
| `? … : []` | 있으면 쓰고, 없으면 빈 배열 |

**영어에는 묵상 데이터가 아예 없습니다.** 그래서 영어로 보면 `explanation` 이 항상 `[]` 이고, 화면 쪽에서 "묵상이 없으면 클릭을 막는" 처리를 하므로 **성화를 눌러도 아무 일이 일어나지 않습니다.**

## 7. 성화 이미지

경로를 만드는 곳은 코드 딱 한 줄입니다.

```ts
image: `/images/rosary/${id}-${d + 1}.jpeg`
```

→ `/images/rosary/joyful-1.jpeg`, `sorrowful-3.jpeg` …

| 항목 | 값 |
|---|---|
| 위치 | `public/images/rosary/` |
| 개수 | 20장 (4신비 × 5단) |
| 이름 규칙 | `{joyful\|sorrowful\|glorious\|luminous}-{1..5}.jpeg` |
| 총 용량 | 약 805 KiB |

**이미지를 바꾸려면** 같은 이름으로 덮어쓰기만 하면 됩니다. 코드는 손댈 필요가 없습니다.

경로가 문자열로 조립되기 때문에 파일이 없어도 **빌드는 통과합니다.** 대신 화면에서 404 가 나고, `RosaryStepView` 가 조용히 숨깁니다.

```tsx
onError={(e) => { e.currentTarget.style.display = "none"; }}
```

> 💡 `public/` 에 넣은 파일은 서비스 워커가 **전부 미리 받아 둡니다**(오프라인 대비). 현재 첫 설치 시 내려받는 2.83 MiB 중 **약 28%가 이 성화 20장**입니다. 큰 이미지를 추가할 때는 이 점을 염두에 두세요. ([06-알려진-문제](06-알려진-문제.md) §11)

## 8. 기도문 원문

`src/lib/prayerTexts.ts` 한 곳에만 있습니다. 두 갈래로 쓰입니다.

```
prayerTexts.ts
   │
   ├─► rosaryMysteries.ts  →  77장으로 쪼개짐   (안내 화면 — 실제로 그려지는 쪽)
   │
   └─► PRAYER_TEXTS.rosaryDecades  →  11개 섹션 통째
        (지금은 화면에 안 그려짐 — CounterGrid 가 [기도문 보기] 링크를 만들지,
         창을 열지 판단하는 존재 표시로만 쓰인다. 지우면 안 됨)
```

둘 다 같은 상수를 가리키므로 **문구를 고칠 일이 생기면 한 곳만 고치면 양쪽이 같이 바뀝니다.**

```ts
export const OUR_FATHER_KO = [
  "하늘에 계신 우리 아버지,",
  "아버지의 이름이 거룩히 빛나시며 아버지의 나라가 오시며",
  ...
];
```

한 칸이 화면에서 한 문단(`<p>`)입니다.

> ⚠️ 문구는 가톨릭 기도서의 현행 공식 문안을 검수해 넣은 것입니다. 어색해 보여도 출처를 확인하지 않고 고치지 마세요.

```
62 ★ 5단: 마리아께서 성전에서 예수님을 찾으심을 묵상합시다 (묵상 11문장)
```
