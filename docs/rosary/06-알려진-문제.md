# 06. 알려진 문제

묵주기도 기능을 전수 조사하면서 실제로 확인한 것들입니다. **일부러 고치지 않고 남겨 두었습니다** — [05-연습문제](05-연습문제.md)의 재료이기 때문입니다.

다만 아래 목록 중 **§1 은 실제 사용자에게 영향이 있는 버그**이고, **§13·14 는 기도 원문 문제**라 성격이 다릅니다.

| 심각도 | 항목 |
|---|---|
| 🔴 사용자 영향 | §1 중복 계수, §13·14 기도 원문 |
| 🟡 어색함 | §2 되돌리기, §3 직접입력, §4 제출, §5 안내문, §16 ESC, §17 배경 클릭 |
| 🟢 정리 대상 | §6~§12, §15 |

§16·§17 은 이 문서를 쓰면서 **브라우저로 직접 재보다가** 발견한 것입니다. 코드만 읽어서는 "잘 동작한다"고 보이는 것들이라, 실제로 돌려 보는 일의 가치를 보여 주는 사례이기도 합니다.

# 데이터 흐름

## 1. 🔴 같은 5단이 두 번 세어진다

**위치**: `src/hooks/useCurrentReport.ts` 의 `addRosarySet`

**재현**:
1. 묵주기도 카운터를 3번 탭 (구슬 3알)
2. [기도문 보기] → 끝까지 넘기기 → [기록하기] → 숫자 +5
3. `rosarySetProgress` 는 **여전히 3**
4. 2번 더 탭하면 또 +5

**원인**: `addRosarySet` 이 `counts` 만 고치고 `rosarySetProgress` 를 비우지 않습니다.

**고치는 법**: [연습문제 중급 8번](05-연습문제.md). 다만 "+5 로 두고 구슬만 비울지" vs "남은 단만 더할지"는 판단이 필요합니다.

---

## 2. 🟡 되돌리기가 직접 입력값을 통째로 날린다

**위치**: `src/hooks/useCurrentReport.ts` 의 `removeRosaryBead` 마지막 갈래

```ts
} else {
  nextCount = 0;   // 구슬 0 이고 5단 미만이면 전부 0
}
```

**재현**: 직접 입력으로 `7` 을 넣고 [−] 를 한 번 누르면 `6` 이 아니라 **`0`**.

**의도된 동작이긴 합니다**(주석에 "그냥 0으로 지운다"고 적혀 있음). 5의 배수가 아닌 숫자는 구슬 체계로 표현할 수 없기 때문입니다. 하지만 데이터 손실 폭이 크고 되돌릴 방법이 없습니다.

**생각해 볼 대안**: `nextCount = count - 1` (한 단만 빼기), 또는 확인 창 띄우기.

---

## 3. 🟡 직접 입력이 남은 구슬을 정리하지 않는다

**위치**: `src/app/page.tsx` 의 `onSetValue={setCount}`

**재현**: 구슬 3알을 채운 뒤 직접 입력으로 `20` 을 넣으면 → `20단 · 구슬 3알`. 이후 2번 탭하면 25단이 됩니다.

**원인**: `setCount` 는 묵주기도를 특별 취급하지 않습니다.

```tsx
const handleIncrement = (key) => { if (key === "rosaryDecades") addRosaryBead(); else … };  // 분기 있음
const handleDecrement = (key) => { if (key === "rosaryDecades") removeRosaryBead(); else … }; // 분기 있음
// setCount 는 그대로 넘어감 ← 분기 없음
```

---

## 4. 🟡 제출할 때 구슬이 경고 없이 사라진다

**위치**: `src/hooks/useCurrentReport.ts` 의 `submit`

```ts
rosarySetProgress: 0,   // 채우다 만 세트는 보고서에 올리지 않는다
```

정책 자체는 맞습니다(5단을 못 채웠으니 보고 대상이 아님). 문제는 **사용자가 이 사실을 모른다**는 것입니다. 제출 확인 문구(`home.submitConfirmBody`)에도 언급이 없습니다.

**생각해 볼 대안**: 구슬이 1알 이상 남아 있을 때만 확인 문구에 한 줄 덧붙이기.

---

## 5. 🟡 "기록했습니다" 안내문이 영영 안 사라진다

**위치**: `src/components/RosaryGuide.tsx` 의 `recorded` 상태

`true` 로 만드는 코드는 있는데 `false` 로 되돌리는 코드가 없습니다. 한 번 기록하면 그 뒤 모든 화면에 문구가 남습니다.

**고치는 법**: [연습문제 중급 6번](05-연습문제.md)

# 코드 정리

## 6. 🟢 죽은 파일 `src/lib/meditations.json`

약 30KB 짜리 JSON 파일인데 **어디에서도 import 되지 않습니다.**

```bash
grep -rn "meditations.json\|from \"./meditations\"" src/    # 결과 없음
```

내용은 `rosaryMeditations.ts` 의 `MYSTERY_MEDITATIONS` 와 완전히 동일합니다. 저장소 루트의 `patch_rosary*.py` 스크립트가 이 JSON 을 읽어 TS 파일에 문자열을 주입한 흔적으로 보입니다.

**지워도 되는가**: 아마도. 다만 앞으로 묵상 데이터를 스크립트로 관리할 생각이라면 JSON 쪽을 원본으로 삼고 TS 를 생성물로 만드는 편이 나을 수도 있습니다. **어느 쪽을 원본으로 삼을지 정하고 하나만 남기세요.**

---

## 7. 🟢 "성호경부터"라는 설명이 사실과 다르다

`src/lib/rosaryMysteries.ts` 의 옛 모듈 주석에 "성호경부터 마침 기도까지"라고 적혀 있었습니다. 실제 첫 단계는 **사도신경**이고, 77장 어디에도 성호경 화면은 없습니다.

*(이 문서를 쓰면서 주석은 이미 고쳤습니다. 기록으로만 남깁니다.)*

**진짜 질문**: 성호경 화면이 **있어야 하는 것 아닐까요?** 실제 묵주기도는 성호경으로 시작합니다. 추가한다면 78장이 됩니다.

---

## 8. 🟢 성화 팝업이 모달을 2중으로 쌓는다

`RosaryGuide.tsx` 의 기록 확인창에는 이런 주석이 있습니다.

> 중첩 `<dialog>` 대신 그냥 이 자리에 그린다. 이미 열려 있는 창 안에 모달을 또 띄우는 것보다, 같은 흐름의 한 단계로 보여 주는 편이 안전하다.

그런데 성화 팝업(`MysteryImageDialog`)은 **`PrayerTextDialog` 의 `<dialog>` 안에서 `showModal()` 을 부릅니다.** 원칙이 한쪽에만 적용된 셈입니다.

**그리고 이게 실제로 문제를 일으키고 있습니다** — 아래 §16(ESC 를 누르면 두 창이 함께 닫힘)이 바로 이 중첩에서 나옵니다. 원칙과 코드가 어긋나 있으니 **원칙을 고치든 코드를 고치든 하나로 맞춰야** 합니다.

---

## 9. 🟢 스와이프가 성화 위에서도 먹는다

스와이프 핸들러가 루트 `<section>` 전체에 붙어 있습니다. 그래서 성화 이미지 위에서 가로로 쓸어도 화면이 넘어갑니다.

성화를 확대해서 보고 싶은 사용자에게는 방해가 될 수 있습니다. 지금은 이미지 확대 기능이 없어 실질 문제는 아니지만, 나중에 핀치 줌 같은 걸 넣으면 충돌합니다.

---

## 10. 🟢 스크린 리더가 진행률을 못 듣는다

`src/components/PrayerTextDialog.tsx` 의 큰 버튼:

```tsx
aria-label={t("counters.tapToRecord")}                      // "탭하여 기록"
…
<span>{incrementCaption ?? t("counters.tapToRecord")}</span>  // "3 / 5단"
```

화면에는 진행률이 보이는데 `aria-label` 은 고정 문구입니다. **묵주기도에서 첫 4번의 탭은 숫자가 안 움직이므로**, 스크린 리더 사용자는 아무 반응이 없다고 느낍니다.

**고치는 법**: [연습문제 고급 12번](05-연습문제.md)의 마지막 부분.

## 11. 🟢 선캐시의 28%가 성화다

| | |
|---|---|
| PWA 첫 설치 선캐시 총량 | 약 2.83 MiB |
| 그중 성화 20장 | 약 805 KiB (**27.8%**) |
| 하루에 실제로 쓰이는 성화 | **5장** |

폰트는 같은 논리로 이미 지연 로딩합니다(`isLazyFont`). 성화에는 적용돼 있지 않습니다.

**그런데 바꾸는 게 옳은지는 별개 문제입니다.** 오프라인 우선 정책과 충돌합니다. 트레이드오프 분석은 [연습문제 고급 14번](05-연습문제.md).

## 12. 🟢 `luminous` 성화만 해상도가 다르다

| 파일군 | 해상도 |
|---|---|
| `joyful-*`, `sorrowful-*`, `glorious-*` | 약 305×407 @ 300dpi |
| **`luminous-*`** | **약 182×249 @ 72dpi** |

출처가 다른 것으로 보입니다. 전체화면 팝업에서 확대하면 빛의 신비만 흐릿합니다.

**고치려면**: 같은 출처의 고해상도 이미지를 구해 `public/images/rosary/luminous-{1..5}.jpeg` 를 덮어쓰면 됩니다. 코드는 손댈 필요가 없습니다.

## 16. 🟡 ESC 를 누르면 기도문 창까지 닫힌다

**브라우저로 실측한 결과입니다.** 성화 팝업이 열린 상태에서 ESC 를 누르면 `dialog[open]` 이 **2 → 0** 이 됩니다. 성화만 닫히길 기대했는데 기도문 창까지 사라집니다.

**원인**: 네이티브 `cancel` 이벤트는 버블링하지 않지만, React 는 이런 이벤트를 최상위에서 받아 **자기 컴포넌트 트리를 따라** 다시 전달합니다. 그래서 부모인 `PrayerTextDialog` 의 `onCancel` 까지 불립니다. `e.preventDefault()` 는 브라우저 기본 동작만 막을 뿐 이 전파는 막지 못합니다.

**고치는 법**: `MysteryImageDialog` 의 `onCancel` 에 `e.stopPropagation()` 추가.

---

## 17. 🟡 배경을 눌러도 팝업이 닫히지 않는다

**실측**: 팝업이 열린 상태에서 화면 구석(5, 5)을 클릭해도 `dialog[open]` 이 **2 그대로**입니다.

**원인**: 닫기 판정이 `e.target === e.currentTarget` 인데, `.fullScreenDialog`(100vw×100vh) 안을 `.fullScreenContent`(100%×100%)가 꽉 채우고 있어 **어디를 눌러도 `<dialog>` 자신이 target 이 되지 않습니다.**

**고치는 법**: `.fullScreenContent` 를 내용 크기만큼만 차지하게 하거나(그러면 진짜 "배경"이 생김), 판정을 `e.target.closest("[class*=fullScreenContent]") === null` 같은 방식으로 바꾸기.

# 기도 원문 — 손대지 않았습니다

아래 셋은 **정확한 문구를 지어낼 수 없어** 기록만 합니다. 출처(가톨릭 기도서, 레지오 교본 등)를 확인해 고칠지는 판단이 필요합니다.

## 13. 🔴 묵상 문장이 빠진 곳

대부분의 단은 문장이 11개이고, 마지막 하나가 꽃다발을 바치는 마무리 봉헌문입니다. 그런데 세 곳은 10개뿐입니다.

| 신비 | 단 | 문장 수 |
|---|---|---|
| 환희(joyful) | 2단 | **10** |
| 환희(joyful) | 3단 | **10** |
| 고통(sorrowful) | 1단 | **10** |

빛의 신비는 전 단이 10개인데, 마무리 기원문이 별도 문장이 아니라 10번째 문장 끝에 이어 붙어 있는 형태입니다. 즉 **다른 신비와 데이터 모양이 다릅니다.**

## 14. 🔴 문장이 잘려 있다

`src/lib/rosaryMeditations.ts` 의 빛의 신비 5단 마지막 문장이 이렇게 끝납니다.

```
"… 영원한 생명의 빵을 빌어주소서. 빛의"
```

**`"빛의"` 라는 조각이 붙어 있습니다.** 복사 과정에서 다음 항목의 첫 단어가 끌려 들어온 것으로 보입니다.

*이 조각만 지우는 것은 내용을 더하지 않는 수정이라 비교적 안전합니다. 다만 뒤에 원래 더 있어야 할 문장이 없는지 확인이 필요합니다.*

## 15. 🟢 연속 공백

묵상 문장 곳곳에 공백이 두 개 이상 이어진 곳이 있습니다.

```
"삼위일체의 하느님은 당신의 아들을  사람으로 탄생시켜 타락한 인류를     구원하기로 정하셨습니다."
                              ↑↑                        ↑↑↑↑↑
```

PDF 나 스캔 문서에서 텍스트를 추출한 흔적입니다. HTML 은 연속 공백을 하나로 합쳐 보여 주므로 **화면에는 표시되지 않습니다.** 검색이나 복사할 때만 걸립니다.

내용을 바꾸지 않는 정리라 안전합니다.

```bash
# 찾기
grep -n '  ' src/lib/rosaryMeditations.ts | head
```
