# 뗏세라 구절별 해설

`/tessera` 화면에서 기도문 구절을 누르면 뜨는 **쉬운 풀이 + 관련 성경** 팝업의 구조와 고치는 방법.

## 파일

| 파일 | 하는 일 |
|---|---|
| `src/lib/tesseraTexts.ts` | 기도문 원문 (건드리지 않는다 — 검수된 전례문) |
| `src/lib/tesseraVerses.ts` | 타입 + `groupSectionLines()` — **로직만** |
| `src/lib/tesseraCommentary.ts` | 71구절의 풀이와 성경 인용 — **데이터만** |
| `src/components/VerseCommentaryDialog.tsx` | 전체화면 팝업 |
| `src/app/tessera/page.tsx` | 구절 버튼 렌더 + 팝업 연결 |
| `src/__tests__/tesseraCommentary.test.ts` | 원문과 해설이 어긋나지 않는지 전수 검사 |

로직과 데이터를 나눈 이유는 `rosaryMysteries.ts` ↔ `rosaryMeditations.ts` 와 같다. 1,300줄짜리 해설이 섞여 있으면 "구절을 어떻게 묶는가"라는 진짜 로직이 스크롤에 파묻힌다.

## 구절은 "줄 범위"다

기도문의 `lines` 는 **화면에 한 문단으로 그리는 단위**지 뜻이 끊기는 단위가 아니다. 까떼나의 마니피캇은 ○/● 를 번갈아 바치느라 성경 한 절이 두 줄로 쪼개져 있다.

```
"○ 내 영혼이 ✝주님을 찬양하고"                 <- 루카 1,46
"내 구원자 하느님 안에서 내 마음 기뻐 뛰노네."   <- 루카 1,47
```

그래서 해설은 **연속된 줄 묶음**에 붙이고, 위치로 가리킨다.

```ts
{ section: 1, from: 0, to: 1, title: "마니피캇 ① …", body: [...], quotes: [...] }
//         ↑ sections 인덱스   ↑ 이 줄 포함  ↑ 이 줄도 포함
```

### 줄 텍스트를 키로 쓰면 안 된다

같은 문장이 여러 곳에 나온다. `"● 저희를 위하여 빌어 주소서."` 는 뗏세라 안에서만 여덟 번 나오고, 성호경(`SIGN_OF_CROSS`)과 까떼나 후렴(`ANTIPHON`)은 아예 **같은 상수를 두 장에서 함께 쓴다**. 문장을 키로 잡으면 "묵주기도 호칭기도의 성 요셉"과 "마침기도의 세례자 요한"에 같은 풀이가 붙어 버린다.

후렴처럼 정말 같은 내용을 두 번 쓸 때는 `ANTIPHON_COMMENTARY` 처럼 지역 상수로 한 번만 적고 `{ ...ANTIPHON_COMMENTARY, section: 2 }` 로 끼워 넣는다.

## 구절을 고치거나 더할 때

1. `tesseraCommentary.ts` 에서 해당 장의 배열을 고친다.
2. `npx vitest run src/__tests__/tesseraCommentary.test.ts` 를 돌린다.

테스트가 검사하는 것:

- `(section, from, to)` 가 실제 있는 줄을 가리키는가
- 같은 section 안에서 범위가 겹치지 않는가
- **176줄이 빠짐없이 덮이는가** (해설 없는 줄이 하나도 없어야 한다)
- `groupSectionLines()` 결과를 이어 붙이면 원래 `lines` 와 같은가
- 모든 구절에 제목·풀이·성경이 있는가, 장절 표기가 「성경」 형식인가
- 구절 수가 71개인가 (구절을 의도적으로 늘렸다면 이 숫자도 함께 고친다)

> ⚠️ `tesseraTexts.ts` 에서 줄을 넣거나 빼면 그 뒤의 해설 번호가 **조용히** 밀린다. 화면에는 엉뚱한 구절에 엉뚱한 풀이가 붙을 뿐 에러가 나지 않으므로, 기도문을 고쳤다면 위 테스트를 반드시 먼저 돌릴 것.

## 성경 본문은 어디서 왔나

한국 천주교 주교회의 「성경」(새번역)이다. 저장소 루트에 두었던 `b-1.pdf` / `b-2.pdf` 에서 뽑았고, 두 파일은 `.gitignore` 에 넣어 **커밋하지 않는다**(4.5MB짜리 저작물 원본이다).

뽑는 과정에서 걸린 문제 하나를 적어 둔다. PDF 는 한글을 어절 중간에서도 끊기 때문에 줄 끝의 띄어쓰기 정보가 사라진다.

```
b-1:  "... 어둠이 심연을 덮고"      원문은 "덮고 하느님의"  (공백 있음)
      "하느님의 영이 그 물 위를"

b-1:  "... 빛과 어둠을 가"          원문은 "가르시어"      (공백 없음)
      "르시어,"
```

한 판본만 보고는 구별할 수 없다. 두 PDF 는 **줄바꿈 폭이 다르므로**, 한쪽에서 줄 중간이라 띄어쓰기가 살아 있는 지점을 정답으로 삼아 대조하면 거의 다 복원된다(34,662절 중 판정 불가 987절, 2.8%). 인용한 절은 모두 눈으로 검수했다.

새 절을 인용하려면 같은 방식으로 뽑아 **본문을 한 번 읽어 보고** 넣는다. 검수 표시(`¿`)가 남은 문자열은 테스트가 막는다.

팝업 하단과 `/tessera` 화면 맨 아래에 출처를 표기한다.

## 풀이를 쓸 때

- 읽는 분이 50대 이상인 것을 전제로 한다. 한자어를 쓰면 곧바로 풀어 준다(`전구(轉求), 곧 대신 빌어 주는 일`).
- `body` 의 한 원소가 한 문단이다. 한 문단은 두세 문장을 넘기지 않고, 구절당 4문단 안팎으로 쓴다.
- 교리를 새로 주장하지 말고 공인된 해설 범위 안에서만 쓴다. 판본 차이가 있는 대목은 그렇다고 밝힌다.
- 풀이는 공식 해설이 아니다. 화면에도 그렇게 적어 두었다.

## 화면 쪽에서 조심할 것

- 구절 버튼 안의 줄은 `<p>` 가 아니라 `<span>` 이다. `<button>` 은 phrasing content 만 담을 수 있어 `<p>` 는 유효하지 않은 HTML 이다. CSS 에서 `display: block` 으로 세운다.
- 버튼에 `aria-label` 을 **달지 않는다**. 달면 버튼의 접근명이 그 문구로 대체되어 스크린리더가 기도문 본문을 읽어 주지 않는다. 지금은 "기도문 전체 + 풀이 보기"가 그대로 읽힌다.
- 인쇄(`@media print`)에서는 `ⓘ 풀이` 칩과 버튼 장식을 모두 숨긴다. 인쇄물은 해설 기능이 없던 때와 똑같이 나와야 한다.
- 팝업의 `onCancel` 에서 `stopPropagation()` 을 함께 부른다. 지금은 `/tessera` 가 다이얼로그가 아니라 문제가 없지만, 나중에 기도문 팝업 안에서 이 컴포넌트를 다시 쓰면 ESC 한 번에 두 다이얼로그가 같이 닫힌다 — `docs/rosary/03-성화-팝업.md` 에 실측이 적혀 있다.
